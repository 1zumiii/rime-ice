# 个人化：用自己的输入微调排序模型

本文说明如何在自己的设备上积累训练语料，并用它微调候选排序模型。**本仓库不包含任何个人语料或个人权重**，微调出来的权重只应留在自己的设备上，不要提交，也不要公开发布。

## 一、为什么个人权重不能公开

排序模型会记住训练数据中少见的、重复出现的内容，例如人名、地名和固定说法。即使模型只给候选打分、不生成文字，别人也可以拿一个候选词去试探，从分数是否异常偏高推断它是否出现在训练数据里。附加参数（LoRA 等）同样会泄露。靠删除人名和数字来“脱敏”不可靠。

因此约定：

- 公开发布的模型只用公开语料训练（见模型仓库的 `DATA.md`）。
- 个人语料、个人权重和选词统计只放在本机用户目录，已加入忽略名单，不进任何仓库（包括私有仓库，因为私有仓库将来可能被改为公开）。

## 二、积累语料

所有记录只在本机，明文，可随时关闭和清空。开关都是用户目录里的空文件（Mac 为 `~/Library/Rime`，手机为 Trime 的 `files/rime`）：

| 开关文件 | 产生的文件 | 内容 |
|---|---|---|
| `select_stats.enabled` | `select_stats.tsv` | 纯数字的选词位次，用于评估，不含任何文字 |
| `select_corpus.enabled` | `select_corpus.tsv` | 训练样本（明文），见下 |

`select_corpus.tsv` 每行 10 列，制表符分隔：

| 列 | 含义 |
|---|---|
| id | 时间戳加序号，用于关联 revise 行 |
| 时间戳 | 精确到分钟 |
| 输入字母数 | 当时输入的拼音字母个数 |
| 上文 | 当时上文的最后 6 个字（取自本会话刚上屏的词，不读取任何应用里的文字） |
| 所选词 | 用户选中的候选 |
| 最终首位 | 重排后排在第一位的候选 |
| 原首位 | Rime 原顺序排在第一位的候选 |
| 类型 | `hard`：所选不是最终首位（模型排错或用户有意选了别的），全部记录；`anchor`：选了最终首位，按 `llm_rerank/select_anchor_rate`（默认 0.1）随机抽样 |
| 距上次上屏秒数 | 越大，上文越可能已不对 |
| 模型 | `q` 为 Qwen，`s` 为学生模型 |

选词后 3 秒内按退格，会追加一行 `revise<Tab>id`，表示该条可能选错了，训练时应丢弃或降权。

关于“只记不在首位的”：难例（所选不是首位）训练价值最高，但只用难例训练会让模型学成“别选首位”，所以保留约 10% 的锚点作对照。锚点同时可用来估计准确率。

### 噪声来源

记录基于输入法自己看到的上屏顺序，而不是文档里的实际文字。移动光标后补充内容时：

- 用方向键、退格、回车移动：上文会被清空，不会记错。
- 用手指或鼠标点击移动：Mac 看不到点击，上文可能不对，此时“距上次上屏秒数”会较大，训练时可据此过滤；安卓端的改版 Trime 能检测到光标被用户点动并清空上文。

## 三、微调

微调脚本在模型仓库里（`personalize/`），输入是 `select_corpus.tsv`，输出是只属于自己的小权重或完整个人模型：

1. 读取语料：丢弃 `revise` 指向的条目；`hard` 条目构造成（上文，所选词）为正例、（上文，最终首位）和（上文，原首位）为反例的成对样本；`anchor` 条目作为不变样本，防止遗忘。
2. 以公开的基础学生模型为起点，用成对排序损失加语言模型正则微调；数据量很小，几分钟即可。
3. 用留出的 10% 个人样本验证：个人模型在这些样本上的首位命中率应高于基础模型，同时在公开评测集上的准确率下降不超过 1 个百分点，否则放弃。
4. 导出为 GGUF 并量化（Q8_0），放到设备的用户目录，不要提交。

数据量参考：少于几千条难例时效果有限，更可靠的做法是先用选词统计确认“重排确实有改进空间”，再决定是否微调。

## 四、清空

删除对应的 `.enabled` 文件即停止记录，删除 `select_stats.tsv`、`select_corpus.tsv`（及其 `.part-*.tsv.gz` 分卷）即清空。
